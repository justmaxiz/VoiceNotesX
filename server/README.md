# VoiceNotes backend

Node.js 24+, TypeScript, Fastify 5 и PostgreSQL. API обслуживает аккаунты, заметки и ИИ; исходное аудио хранится в закрытой папке сервера. Машинный контракт: `GET /api/v1/openapi.json`; общие типы web/Expo: `src/contracts.ts`.

## Локальный запуск

1. Установите Node.js 24+ и зависимости: `npm install` и `npm --prefix server ci` из корня проекта.
2. Выполните `powershell -File server/scripts/configure-local-data.ps1`. Скрипт создаёт `server/.env`, генерирует локальные пароли и JWT secret, сохраняя существующие значения.
3. При установленном Docker Desktop: `npm run backend:db:up`. PostgreSQL доступна только на `127.0.0.1:5433`, данные сохраняются в volume. `backend:db:down` не удаляет volume.
4. Выполните `npm run backend:migrate`, затем `npm run backend:dev` и в другом терминале `npm run dev`.
5. Создайте аккаунт в клиенте. `/api` проксируется Vite на порт 3001; `VITE_API_URL` нужен только при отдельном origin API.

Без Docker можно использовать свою PostgreSQL: создайте отдельные роли migrator/runtime и укажите `MIGRATION_DATABASE_URL` / `DATABASE_URL`. Скрипты выдачи прав находятся в `postgres/init/`. Runtime имеет права на данные, migrator — на изменение схемы. Миграции используют блокировку, контрольные суммы и транзакции; повторный запуск безопасен. Изменение уже применённой миграции считается ошибкой: новые изменения оформляются новым SQL-файлом.

Проверки: `npm run backend:test` поднимает отдельную настоящую PostgreSQL через `embedded-postgres` на свободном локальном порту и временное аудиохранилище. Доступ к Docker и живым ИИ API не требуется. Сборки: `npm run build`, `npm run backend:build`. Запуск сборки: `npm run backend:start`.

## ИИ-сводки (блок 10)

Перед запуском обновлённого API примените новую миграцию `003-summaries.sql`: `npm run backend:migrate` из корня. Применённые миграции не изменены. Новые таблицы получают runtime-права через default privileges migrator. `npm run backend:dev` / `backend:start` запускает также очередь сводок и вечерний scheduler. Node API должен работать непрерывно; браузер для scheduled генерации не нужен. Пользователь задаёт timezone/локальное время в профиле; по умолчанию 21:00. Без настроенного timezone автоматического запуска нет.

Контракты, точные API-пути, DST/catch-up, кеш, лимиты, восстановление lease и ограничения данных описаны в [SUMMARY-CONTRACTS.md](../docs/SUMMARY-CONTRACTS.md). Бюджеты настраиваются `SUMMARY_*` из `.env.example`. Ошибка ИИ сохраняет старый успех и предоставляет отдельную фактическую версию; GET никогда не вызывает LLM. Старые локальные отчёты не импортируются автоматически. [Приёмка блока 10](../tasks/ACCEPTANCE-61-72.md).

Для отдельной визуальной проверки на синтетических данных: из `server/` запустите `node --import tsx test/summary-preview.ts`. Он поднимает временную отдельную PostgreSQL, provider double и Vite на `http://127.0.0.1:5178`, не читая `.env` или пользовательскую БД. Учётная запись: `summary-preview@test.invalid`, пароль: `synthetic-preview-password`. `Ctrl+C` останавливает процессы; временный каталог остаётся в системной temp. Это не live/staging smoke.

## API и сессия (подробности)

Потоковая диктовка в режиме разработки: WebSocket `/api/v1/dictation/live?language=ru-RU` (`en-US` и `auto` также поддерживаются). Требует разрешённого Origin и действующей сессии. Клиент передаёт бинарный mono PCM16 little-endian, 16 kHz, после сообщения `{ "type": "ready" }`. Сервер возвращает `{ "type": "transcript", "transcript": "...", "interim": "..." }`; команда `{ "type": "finish" }` завершает поток и возвращает `{ "type": "done", "text": "..." }`. Распознавание использует Gemini Live Transcribe с ключом только на сервере. Аудио диктовки не сохраняется, обработка заметки получает текст. Vite проксирует WebSocket; отдельный reverse proxy должен поддерживать Upgrade. Региональные ограничения и лимиты Gemini возвращаются как ошибка диктовки. Этот маршрут выключен для production/Alice; импорт аудио через SpeechKit сохраняет существующую обработку.

Все пользовательские маршруты начинаются с `/api/v1`. `health` проверяет процесс; `ready` проверяет подключение к БД и возвращает 503 при сбое. Заметки поддерживают CRUD, пагинацию, поиск, сортировку и фильтр расписания. Владелец определяется только серверной сессией. Добавление или снятие расписания сохраняет ID заметки.

Пароли хранятся как salted scrypt hash. Access JWT действует 15 минут и остаётся в памяти web-клиента. Refresh token действует 30 дней, хранится в HttpOnly SameSite=Strict cookie, вращается при обновлении; повторное использование старого токена отзывает всю семью сессии. Web auth-запросы требуют разрешённый `Origin`. Expo передаёт `platform: "expo"` при входе, получает refresh token в JSON и хранит его в защищённом хранилище платформы; обновление/выход передают его в теле. Медиа принимает refresh cookie web-клиента либо Bearer Expo, поддерживает HTTP Range.

При первом входе клиент предлагает перенос IndexedDB. Импорт пакетами сохраняет исходник до подтверждения ID/количества сервером; `(owner, legacyId)` защищает от дублей. Существующие аудиоблобы переносятся без повторного ИИ-анализа. Стандартные демо-записи не импортируются.

## ИИ и аудио

Development: `AI_PROVIDER=gemini`, `GEMINI_API_KEY` на сервере, только синтетические данные. Production: `AI_PROVIDER=alice`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`; конфигурация Gemini в production отклоняется. Alice анализирует текст, SpeechKit v3 распознаёт аудио после преобразования в Ogg Opus. Большое dev-аудио использует Gemini Files API с удалением файла после распознавания.

Загрузка принимает MP3/M4A/WAV/WebM/OGG, максимум 100 MiB и 2 часа. Формат и длительность проверяются ffprobe/ffmpeg до вызова ИИ. Бинарники устанавливаются зависимостями; можно задать `FFMPEG_PATH` и `FFPROBE_PATH`. На сервере ограничены параллельные загрузки/ИИ-запросы и очередь одного владельца.

Jobs сохраняются в PostgreSQL и восстанавливаются после перезапуска. Транскрипт сохраняется отдельно от анализа, повтор анализа не запускает распознавание заново. Извлечённые действия сохраняются только после явного выбора пользователя. Короткая диктовка удаляет raw audio после успеха или ошибки; импортированный файл хранится 14 дней. Фоновая очистка удаляет файл, сохраняет текст/сводку/заметки и повторяет неудачные удаления. Каталог аудио не публикуется статическим сервером; expired file возвращает 410.

## Развёртывание

Production-БД, аудио и backups размещаются в РФ. Используйте HTTPS reverse proxy с передачей `/api/v1` и приватный persistent volume для `AUDIO_STORAGE_PATH`. `CORS_ORIGINS` задаётся явно, без wildcard; web и API должны позволять SameSite cookie, предпочтительно под одним origin. `.env`, ключи, исходники аудио и backups не включаются в Git. Выполняйте миграции ролью migrator перед запуском новой версии. Бэкап включает PostgreSQL и приватные файлы; runtime не должен иметь DDL-права.

Результаты автоматической приёмки и отдельный staging/live smoke: `../tasks/ACCEPTANCE-45-60.md`. Автотесты не подтверждают доступность настоящих ключей и инфраструктуры.
