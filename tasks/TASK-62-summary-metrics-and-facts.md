# TASK-62: Серверные метрики и проверяемые факты сводки

- **ID:** `TASK-62`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-61`, `TASK-49`

## Цель

Считать показатели обычным кодом по данным PostgreSQL и выдавать факты, на которые может ссылаться ИИ. Получение всех записей браузером не должно быть условием корректности отчёта.

## Объём работ

- Выделить сервис выборки и чистые функции агрегации; учитывать только записи авторизованного владельца. Чтение исходников и агрегатов для одного отчёта выполняется в согласованном снимке БД.
- Выбирать завершения по текущему `completedAt`, созданные записи по `createdAt`, открытые задачи с расписанием периода, все актуальные старые просрочки и ближайшие сроки. Разделить ретроспективу периода и текущее внимание; у каждого факта указать основание времени.
- Считать завершённые записи, новые записи с/без расписания, открытые сроки, просрочки, ближайшие дедлайны, распределение по датам/приоритетам/тегам, текущее состояние чек-листов и сопоставимые изменения числа завершений.
- Для тегов определить семантику нескольких тегов, нормализацию и дедупликацию; одну запись не считать дважды в общих итогах. Категорию учитывать и при пустом массиве `tags`.
- Не считать `updatedAt` выполненной работой; не выводить прирост чек-листа без прежнего состояния. `completedAt` архивной записи обычно очищается: такие завершения не восстанавливать.
- Архивные записи исключать из текущего внимания; описать влияние исключения архивных/удалённых/повторно открытых записей на пересчёт прошлого периода. Старые сохранённые отчёты остаются снимками.
- Пересечения расписания рассчитывать отдельно от просрочек. Дедлайн не обязательно является окончанием реально выполненной работы; записи на весь день не трактовать как 24 часа труда.
- Плановые длительности показывать с покрытием данных. Отсутствующий `estimatedMinutes` не заменять стандартным часом в аналитике. Происхождение существующих автоматически вычисленных оценок неизвестно: не объявлять их явными оценками пользователя или фактическими часами.
- Не вводить норму рабочего дня или оценку «перегружен» без настройки ёмкости; в первой версии показывать объективные пересечения и плановую плотность с оговоркой.
- Создать детерминированные факты: ID, тип, числовое значение/даты, источники, время среза. Статистику рассчитывать по полному набору независимо от лимита LLM-выборки.
- Старые импортированные временные метки считать текущими доступными данными, не подтверждённой историей завершений; обозначить ограничение покрытия.

## Критерии приёмки

- Задачи со старым просроченным сроком попадают в внимание, даже если срок вне периода.
- Более 200 записей обрабатываются без усечения статистики; выборки разных пользователей изолированы.
- Формулировки различают количество закрытий, текущий план и фактическую продуктивность.
- Пустые данные, неизвестные длительности и отсутствие сравнения имеют отдельное корректное представление.

## Проверки

- Unit-тесты границ дня, завершения после полуночи, старых просрочек, тегов, all-day и неполных оценок.
- Интеграционные проверки с тестовой PostgreSQL: два владельца, большой набор и согласованность снимка. Живой LLM не нужен.

## Результат реализации

Контракты, код и ограничения описаны в [документации сводок](../docs/SUMMARY-CONTRACTS.md), проверки — в [отчёте приёмки 61–72](ACCEPTANCE-61-72.md). Изменения оставлены без коммита для ревью.
