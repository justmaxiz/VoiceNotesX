# TASK-54: Серверное структурирование текста через ИИ

- **ID:** `TASK-54`
- **Блок:** 9. Облачный backend и ИИ-обработка ввода
- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Критический (P0)
- **Зависимости:** `TASK-45`, `TASK-46`, `TASK-47`

## Цель

Перенести обработку пользовательского текста на Node backend и возвращать проверенную структуру заметки без вызова модели из браузера.

## Контекст и связанные части проекта

Сейчас `src/lib/gemini.ts` поддерживает необязательный proxy, а `geminiStructuring.ts` парсит модельный JSON. Локальный Node backend уже поднят и предоставляет health endpoint; AI-маршрут ещё не создан. Провайдер выбирается только конфигурацией сервера: Gemini во время разработки, Alice AI через прямой API Yandex AI Studio в production.

## Объём работ

- Создать защищённый endpoint обработки текста, принимающий текст, настройки режима/стиля и локальный контекст даты.
- Реализовать серверный интерфейс провайдера с двумя адаптерами: Gemini для development/test и Alice AI через прямой API Yandex AI Studio для production.
- Запрещать Gemini при `NODE_ENV=production`; production-конфигурация должна явно выбирать Alice и завершаться понятной ошибкой при отсутствии её серверных credentials.
- Хранить ключи Gemini и Yandex только в серверном secret store/env; клиент не получает ключи и не обращается напрямую к провайдерам.
- Использовать для Gemini только синтетические данные в изолированной dev-среде; не направлять в него персональные данные пользователей.
- Адаптировать системный prompt и response schema: возвращать поля содержания, расписания, приоритета, категории, сводки и чек-листа, но не `entity_type`.
- Проверять пустой/некорректный JSON, обязательные поля и даты до отправки ответа клиенту.
- Возвращать нормализованные ошибки provider unavailable, timeout, empty response и invalid response без тихого перехода на локальные эвристики; UI должен позволять повторить запрос.

## Критерии приёмки

- Авторизованный запрос проходит через backend, вызывает выбранный для среды provider и возвращает DTO по `TASK-47`.
- Автотесты подтверждают матрицу `development → Gemini`, `production → Alice`, а production-конфигурация с Gemini отклоняется.
- Секрет модели отсутствует в клиентском bundle и сетевых ответах.
- Невалидный/пустой ответ модели не сохраняется как валидная структурированная запись.
- При недоступности выбранного provider клиент получает стабильный код ошибки, пригодный для повтора и показа пользователю.

## Проверки

- Unit-тесты выбора provider, запрета Gemini в production, prompt mapping, JSON/schema validation и преобразования ошибок.
- Endpoint tests с подменными Gemini/Alice адаптерами для валидного JSON, пустого ответа, malformed JSON, таймаута и отказа сервиса.
- Сборка Node server без действующих AI-секретов; live-smoke провайдера выполняется отдельно только на синтетических данных.
