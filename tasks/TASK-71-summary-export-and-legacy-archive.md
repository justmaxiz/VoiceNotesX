# TASK-71: Экспорт новых сводок и сохранение старого локального архива

- **ID:** `TASK-71`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Обычный (P2)
- **Зависимости:** `TASK-61`, `TASK-69`, `TASK-70`

## Цель

Сохранить копирование/Markdown-экспорт и доступ к ранее созданным локальным отчётам при переходе на серверную систему.

## Объём работ

- Создать общий formatter проверенного API-отчёта для копирования и Markdown: период, timezone, `asOf`, режим/актуальность, метрики, итог, результаты, внимание, направления, предложения и ссылки/идентификаторы источников.
- Использовать один formatter в обоих действиях; исправить нынешнее отсутствие блока внимания в копируемом тексте. Пустые секции не выводить.
- Экспортировать сохранённый снимок, а не пересчитывать показатели по текущему `items`. Сокращение/покрытие и статус исторического снимка остаются понятны вне приложения.
- Не помещать credentials, приватные аудио URL или транскрипты в экспорт. Пользовательский текст выводить безопасно в UI и корректно форматировать в Markdown.
- Обработать отказ clipboard/download; показывать «Скопировано» только после успешной записи, filename сделать безопасным и стабильным.
- Оставить доступный owner-scoped localStorage-архив прежнего формата отдельным блоком «Локальные отчёты прежней версии», с доступом к просмотру/экспорту.
- Не объединять legacy с серверной аналитикой и не загружать их автоматически в БД. Не привязывать старый несегментированный ключ/anonymous-архив к текущему аккаунту автоматически; такие данные не показывать другому владельцу.
- Повреждённый legacy JSON не должен ломать страницу. Переход не удаляет старые данные и не генерирует их заново.
- После перехода всех consumers убрать неиспользуемый локальный генератор и его ложные AI-уведомления; оставить небольшой read-only legacy adapter, если нужен для архива.

## Критерии приёмки

- Копирование и экспорт содержат одинаковые факты/блоки и не расходятся с карточкой отчёта.
- Старые отчёты доступны владельцу, явно отделены и не исчезают при обновлении приложения.
- Ошибка clipboard и повреждённый архив обрабатываются без ложного успеха/потери данных.
- В приложении остаётся один действующий генератор периодических сводок — серверный.

## Проверки

- Изолированные formatter/legacy/UI тесты: пустые секции, все блоки, malformed JSON, account isolation и rejected clipboard.
- Клиентская сборка; полный Vitest только если очистка затрагивает архитектурные компоненты по `AGENTS.md`.
