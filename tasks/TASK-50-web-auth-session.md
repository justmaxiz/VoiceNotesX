# TASK-50: Вход в веб-клиент и сессия пользователя

- **ID:** `TASK-50`

- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Критический (P0)
- **Зависимости:** `TASK-46`

## Цель

Подключить веб-клиент к Node auth API, чтобы сервер мог отделять данные разных пользователей.

## Контекст и связанные части проекта

В приложении нет login/session flow. `App.tsx` и `AppLayout` запускают рабочее пространство сразу, а данные загружаются локально.

## Объём работ

- Добавить экран/состояния регистрации, входа, выхода, восстановления сессии и истёкшей сессии.
- Передавать access token в API client через единый session provider; хранить его в памяти, обновлять сессию через HttpOnly refresh cookie и не сохранять токены в localStorage.
- До восстановления сессии не запускать загрузку и изменение пользовательских данных.
- При `401` выполнить один синхронизированный refresh и повтор исходного запроса; если обновление отклонено, очистить сессию и показать вход. Исключить бесконечные повторы и гонку одновременных refresh.
- Подключить CSRF/Origin-защиту auth API и cookie credentials; хранить в Vite env только адрес собственного API, без credentials базы, JWT-ключа или AI-секретов.

## Критерии приёмки

- После входа клиент восстанавливает сессию и передаёт bearer token серверу.
- Выход очищает пользовательское состояние приложения и не показывает прежние данные следующему пользователю.
- Без сессии нельзя открыть пользовательские данные; истёкший access token обновляется через refresh-сессию, а окончательный отказ приводит к повторному входу.

## Проверки

- Компонентные тесты входа, ошибки авторизации, восстановления и выхода.
- Unit-тест API client для токена, одного refresh при параллельных `401`, отказа refresh и очистки сессии.
