# TASK-58: Компактный прогресс загрузки и анализа аудио

- **ID:** `TASK-58`
- **Блок:** 9. Облачный backend и ИИ-обработка ввода
- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-50`, `TASK-56`

## Цель

Показывать состояние аудиофайла в компактном виджете, пока backend его загружает, транскрибирует и анализирует.

## Контекст и связанные части проекта

`AppLayout` содержит глобальный Quick Capture, но интерфейса импорта файлов и длительных processing jobs нет. Backend из `TASK-56` возвращает job ID, transcript и фактический статус.

## Объём работ

- Добавить выбор аудиофайла поддерживаемых форматов и предварительную проверку размера.
- Показывать закреплённый компактный widget с именем файла, транскриптом по мере появления и текущим этапом обработки.
- Показывать процент только во время этапов, где есть измеримый прогресс; для остальных показывать названия этапов и индикатор ожидания.
- Опросить job status API, переживать переходы между разделами и восстанавливать незавершённые jobs после перезагрузки клиента.
- По успешному завершению показать уведомление «Аудио проанализировано» с действием просмотра кандидатов; при ошибке предложить повтор и сохранить контекст файла, пока доступно.

## Критерии приёмки

- Виджет остаётся видимым при переходе между страницами и показывает стадии без выдуманного процента.
- Пользователь видит транскрипт, когда он готов, и статус ошибки/повтора при сбое.
- После завершения уведомление открывает список извлечённых действий.
- После перезагрузки клиент восстанавливает отображение незавершённой job по серверному ID.

## Проверки

- Компонентные тесты стадий, реального upload progress, transcript-ready, success, error/retry и восстановления job.
- Тесты доступности статуса без цветовой индикации как единственного сигнала.

## Зависимости

- `TASK-50` — веб-сессия и API client.
- `TASK-56` — upload/job endpoint.
