## 1. Executive Summary

This report presents an architectural investigation of the calendar and scheduling UI in VoiceNotes AI to establish the implementation blueprint for **Requirement R3** (*"Tasks must visually stretch across their time duration from `startDate` to `deadline` on the schedule grid"*).

### Key Discoveries:
1. **Existing Architecture is Point-Item Constrained**:
   Currently, tasks on both the Week view (`WeekTimelineView.tsx`) and Day view (`CalendarPage.tsx`) are rendered as isolated point badges inside discrete hour rows (`div` per hour). Tasks are filtered strictly by `parseInt(time.split(':')[0], 10) === hour`. They have zero visual duration, cannot span multiple hours due to DOM row isolation, and completely ignore the existing `estimatedMinutes` field.
2. **Acceptance Criteria Requirement**:
   The acceptance criteria state:
   > *"Агент-судья подтверждает по коду верстки: высота или ширина блока задачи в календаре пропорциональна разнице между `deadline` и `startDate`."*
   To satisfy this with mathematical precision, the timeline layout must transition from row-sliced divs to a **Continuous Column Timeline with Absolute Positioning**.
3. **Deterministic Math & Algorithmic Foundations**:
   - Height formula: `height = Math.max(minHeight, (endMinutes - startMinutes) * (hourHeight / 60))`
   - Top offset formula: `top = (startMinutes - 480) * (hourHeight / 60)`
   - Collision handling: Greedy interval partitioning algorithm ($O(N \log N)$) partitioning overlapping tasks into side-by-side sub-columns (`width = (100 / totalCols)%`, `left = (col * width)%`).
   - Fallback hierarchy for missing `startDate`: Uses `estimatedMinutes` (e.g. `deadline - estimatedMinutes`) or default 30-minute block with a distinctive styling cue.

## 3. Analysis of Current Rendering Mechanics (Point Items)

### 3.1 Week Timeline View (`WeekTimelineView.tsx`)
In `WeekTimelineView.tsx`, the timeline grid is generated by iterating over hours:
```tsx
// Lines 90-112:
{hours.map((hour) => {
  const hourStr = `${hour.toString().padStart(2, '0')}:00`
  return (
    <div key={hour} className="grid grid-cols-8 min-h-[56px] group">
      {/* Col 0: Hour Label */}
      <div className="p-2 text-xs font-mono text-outline ...">{hourStr}</div>

      {/* Cols 1..7: Day cells for this single hour */}
      {weekDays.map((col) => {
        const dayTasks = getTasksForDay(col.dateKey).filter((t) => {
          if (t.isAllDay) return false
          const time = t.dueTime || (t.dueDate?.includes(':') ? t.dueDate : null)
          if (!time) return false
          const taskHour = parseInt(time.split(':')[0], 10)
          return taskHour === hour
        })

        return (
          <div key={`${col.dateKey}-${hour}`} className="p-1.5 border-r ...">
            {dayTasks.map((task) => (
              <div key={task.id} className="p-1.5 rounded-lg text-[11px] truncate ...">
                <div className="truncate">{task.title}</div>
                <div className="text-[10px] text-outline mt-0.5">{task.dueTime || task.dueDate}</div>
              </div>
            ))}
          </div>
        )
      })}
    </div>
  )
})}
```

#### Why this prevents duration stretching:
1. **DOM Isolation**: Each hour row is an independent DOM node `<div key={hour} className="grid grid-cols-8 min-h-[56px]">`. An element inside `hour = 10` is trapped within that row's bounding box.
2. **Filter Predicate**: `taskHour === hour` matches only the start hour (or due time hour). A task spanning from 10:00 to 14:00 is evaluated as false for hours 11, 12, 13, and 14.
3. **No Vertical Scale**: The card height is determined by static text padding (`p-1.5 text-[11px] leading-snug`), not by time span.

## 4. Architectural Transformation for R3: Continuous Column Timeline

To achieve visual stretching proportional to $(deadline - startDate)$, both Week and Day views must adopt the standard continuous column architecture.

### 4.1 Structural Model Comparison
```
CURRENT (Row-Slices):
Hour 08:00  [ Col 0 | Mon cell | Tue cell | ... ]  <-- Independent div
Hour 09:00  [ Col 0 | Mon cell | Tue cell | ... ]  <-- Independent div
Hour 10:00  [ Col 0 | Mon cell | Tue cell | ... ]  <-- Independent div (cannot stretch into 11:00)

PROPOSED (Continuous Columns):
Grid Container (relative, height = totalHours * hourHeight)
├── Col 0: Time Labels (absolute / flex ticks)
├── Col 1 (Mon): Continuous relative container (height = totalHours * hourHeight)
│     ├── Background: 15 horizontal guide lines (border-b) + click targets
│     └── Foreground: Stretched Task Cards (position: absolute; top: ...px; height: ...px)
├── Col 2 (Tue): Continuous relative container ...
└── ...
```

### 4.2 Mathematical Formulas for Placement and Sizing

Let:
- $H_{\text{start}} = 8$ (Grid starts at 08:00 $\rightarrow 480$ minutes from midnight)
- $H_{\text{end}} = 22$ (Grid ends at 22:00 $\rightarrow 1320$ minutes from midnight)
- $\text{HOUR\_HEIGHT} = 64\text{ px}$ (Tailwind `h-16`, 4rem)
- $\text{MIN\_HEIGHT} = 28\text{ px}$ (ensures readability for ultra-short tasks)
- $t_{\text{start}}$ = Task start time in minutes from midnight ($0 \le t_{\text{start}} < 1440$)
- $t_{\text{end}}$ = Task deadline in minutes from midnight ($0 < t_{\text{end}} \le 1440$)
- $\Delta t = t_{\text{end}} - t_{\text{start}}$ (Task duration in minutes)

#### 1. Top Offset Formula:
$$\text{topPx} = \frac{t_{\text{start}} - (H_{\text{start}} \times 60)}{60} \times \text{HOUR\_HEIGHT}$$
$$\text{topPx} = (t_{\text{start}} - 480) \times \frac{64}{60} = (t_{\text{start}} - 480) \times 1.0667\text{ px}$$

#### 2. Height Formula (Proportional to Duration):
$$\text{rawHeightPx} = \frac{\Delta t}{60} \times \text{HOUR\_HEIGHT} = (t_{\text{end}} - t_{\text{start}}) \times \frac{64}{60}$$
$$\text{heightPx} = \max(\text{MIN\_HEIGHT}, \text{rawHeightPx})$$

**Verification of Proportionality**:
- 30 minutes $\rightarrow 32\text{ px}$
- 60 minutes $\rightarrow 64\text{ px}$
- 90 minutes $\rightarrow 96\text{ px}$
- 120 minutes $\rightarrow 128\text{ px}$
- 180 minutes $\rightarrow 192\text{ px}$
Height scales linearly and strictly with duration $\Delta t$, directly satisfying the acceptance criteria.

## 5. Edge Cases & Algorithmic Handling

### 5.1 Fallback Representation When `startDate` is Missing
Tasks may enter the calendar with incomplete date/time pairs. We define a deterministic fallback matrix:

| Condition | Resolution | UI Rendering & Visual Treatment |
| :--- | :--- | :--- |
| **`startDate` + `deadline` present** | Exact interval: $[t_{\text{start}}, t_{\text{end}}]$ | Solid border, full stretch from top to bottom. |
| **`deadline` present, `startDate` missing, `estimatedMinutes` present** | $t_{\text{start}} = t_{\text{end}} - \text{estimatedMinutes}$ | Stretched block with duration $=\text{estimatedMinutes}$. Subtitle shows `"~Ориентировочно с HH:mm"`. |
| **`deadline` present, `startDate` missing, no `estimatedMinutes`** | Fallback duration: 30 minutes ending at deadline ($t_{\text{start}} = t_{\text{end}} - 30$). | Compact card ($32\text{ px}$) ending at deadline, with dashed left accent border (`border-dashed border-l-3`) and milestone icon `flag`. |
| **`startDate` present, `deadline` missing** | $t_{\text{end}} = t_{\text{start}} + (\text{estimatedMinutes} \parallel 60)$ | Stretched block starting at $t_{\text{start}}$, fading bottom border with downward gradient to indicate open end. |
| **Neither `startDate` nor `deadline` present** | Task is unscheduled | Remains in `UnscheduledTasksSidebar` ("Бэклог без даты"), not rendered on grid. |
| **`isAllDay === true`** | All-day event | Placed in the top **"Весь день"** section strip; does not clutter the hourly grid. |

### 5.2 Multi-Day Tasks & Tasks Spanning Outside Visible Hours (08:00–22:00)

#### Case 1: Tasks Spanning Outside 08:00–22:00 (Within Same Day)
- **Start before 08:00 (e.g. 06:30–10:00)**:
  - Clamp top: `clampedStart = Math.max(480, startMinutes) = 480` ($\text{top} = 0\text{ px}$).
  - Height calculated on visible span: `height = (endMinutes - 480) * (64 / 60)`.
  - Visual cue: Top badge with `arrow_upward` icon and label `"С 06:30"`.
- **End after 22:00 (e.g. 20:00–23:30)**:
  - Clamp end: `clampedEnd = Math.min(1320, endMinutes) = 1320`.
  - Visual cue: Bottom badge with `arrow_downward` icon and label `"До 23:30"`.

#### Case 2: Multi-Day Tasks (Spanning Across Midnight / Multiple Days)
- If a task duration $> 24$ hours or dates span multiple days:
  - Modern calendar standard: Render multi-day tasks in the top **All-Day / Multi-Day Banner Strip** (`lines 64-88` of `WeekTimelineView.tsx`).
  - In Week view: Span horizontally across the day columns (`col-span-N`).
  - In Month view: Display a chip on each day within the range $[startDate.date, deadline.date]$.

### 5.3 Overlapping Tasks & Layout Collision Resolution (Sub-Column Partitioning)
When multiple tasks occur during overlapping intervals in the same day column:
Without collision management, cards would overlap at `width: 100%`, obscuring each other.

#### The Algorithm: Greedy Interval Partitioning into Sub-Columns
```ts
export interface PositionedTask {
  task: Item
  topPx: number
  heightPx: number
  leftPercent: number
  widthPercent: number
  zIndex: number
  isFallbackStart: boolean
}

export function layoutDayTasks(
  intervals: ParsedInterval[],
  gridStartHour = 8,
  hourHeight = 64,
  minHeight = 28
): PositionedTask[] {
  if (intervals.length === 0) return []

  // 1. Sort ascending by start time, then duration descending
  const sorted = [...intervals].sort((a, b) => 
    a.startMin !== b.startMin ? a.startMin - b.startMin : b.durationMin - a.durationMin
  )

  // 2. Identify connected overlapping clusters
  const clusters: ParsedInterval[][] = []
  let currentCluster: ParsedInterval[] = []
  let clusterEnd = -1

  for (const item of sorted) {
    if (currentCluster.length === 0) {
      currentCluster.push(item)
      clusterEnd = item.endMin
    } else if (item.startMin < clusterEnd) {
      // Overlaps with current cluster
      currentCluster.push(item)
      clusterEnd = Math.max(clusterEnd, item.endMin)
    } else {
      // New disjoint cluster
      clusters.push(currentCluster)
      currentCluster = [item]
      clusterEnd = item.endMin
    }
  }
  if (currentCluster.length > 0) clusters.push(currentCluster)

  // 3. For each cluster, greedily assign sub-column indices
  const positioned: PositionedTask[] = []

  for (const cluster of clusters) {
    const colEnds: number[] = []
    const assignments: { item: ParsedInterval; col: number }[] = []

    for (const item of cluster) {
      let placedCol = -1
      for (let c = 0; c < colEnds.length; c++) {
        if (colEnds[c] <= item.startMin) {
          placedCol = c
          colEnds[c] = item.endMin
          break
        }
      }
      if (placedCol === -1) {
        placedCol = colEnds.length
        colEnds.push(item.endMin)
      }
      assignments.push({ item, col: placedCol })
    }

    const totalCols = Math.max(1, colEnds.length)
    const widthPercent = 100 / totalCols

    for (const { item, col } of assignments) {
      const topPx = ((Math.max(480, item.startMin) - 480) / 60) * hourHeight
      const clampedEnd = Math.min(1320, item.endMin)
      const duration = clampedEnd - Math.max(480, item.startMin)
      const heightPx = Math.max(minHeight, (duration / 60) * hourHeight)

      positioned.push({
        task: item.task,
        topPx,
        heightPx,
        leftPercent: col * widthPercent,
        widthPercent,
        zIndex: 10 + col,
        isFallbackStart: item.isFallbackStart,
      })
    }
  }

  return positioned
}
```

#### Collision Visual Output:
- Two concurrent tasks get: `width: calc(50% - 3px)`, `left: 0%` and `left: 50%`.
- Three concurrent tasks get: `width: calc(33.33% - 3px)`, `left: 0%`, `left: 33.33%`, `left: 66.66%`.
- On hover: `hover:z-50 hover:shadow-lg` allows the user to bring any card forward to inspect its full text.

## 7. Concrete Recommendations & Implementation Checklist for R3

Create a pure, thoroughly unit-tested layout utility:
1. `parseTaskInterval(task: Item, targetDateKey: string): TaskInterval | null`

2. `layoutDayTasks(intervals, gridStartHour, hourHeight, minHeight): PositionedTask[]`
   - Implements the greedy interval partitioning algorithm with pixel `topPx`, `heightPx`, `leftPercent`, and `widthPercent`.

### Phase 2: Refactor `WeekTimelineView.tsx`
1. Replace row-based `hours.map` grid with the Continuous Column layout (Column 0: Time labels, Columns 1..7: Day relative columns).
2. Render background hour guide lines with click-to-add handler for `openQuickCapture`.
3. Render foreground stretched tasks using `layoutDayTasks`.
4. Add time-range label on stretched cards: e.g. `"10:00 – 11:30"` (or `"15:00 Дедлайн"` for compact fallbacks).

### Phase 3: Refactor Day View in `CalendarPage.tsx`
1. Convert Day View from 15 separate row divs to a continuous single-day column.
2. Apply `layoutDayTasks` to today's tasks.
3. Add a dedicated "Весь день" banner in Day View for all-day tasks.

### Phase 4: Update `DateTimePicker.tsx` & `SlideOverDrawer.tsx`
1. Add input fields for `startDate` / `startTime` alongside existing `dueDate` / `dueTime`.

### Phase 5: Vitest Test Suite (`src/components/calendar/__tests__/`)
Add tests verifying:
- Height of rendered element is proportional to $(\text{deadline} - \text{startDate})$: e.g. a 2-hour task has exactly double the height of a 1-hour task.

- Fallback for missing `startDate` renders with expected fallback height (`estimatedMinutes` or 30m).
- All-day tasks render in the all-day section without occupying the hourly grid.
