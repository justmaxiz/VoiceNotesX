# TASK-64: PostgreSQL-хранилище отчётов, настроек и заданий

- **ID:** `TASK-64`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-61`, `TASK-48`, `TASK-45A`

## Цель

Сохранять готовые сводки и устойчивые задания на сервере, обеспечить общий архив аккаунта и восстановление генерации после перезапуска.

## Объём работ

- Создать новую SQL-миграцию; не изменять применённые миграции. При необходимости обновить выдачу runtime-прав новым таблицам.
- Хранить отчёт: владелец, нормализованный период/фильтры, `asOf`, `generatedAt`, метрики, проверенный LLM JSON или фактический fallback, минимальные источники/факты, отпечаток входа, версии схемы/промпта/конфигурации модели, сведения покрытия.
- Разделить логический слот отчёта и его версии: первая генерация/обновление одного периода не создаёт дубли карточек. Предыдущая успешная версия доступна до публикации следующей.
- Хранить задания отдельно от отчётов: stage, attempt count, next attempt, lease, owner, ключ запроса, trigger (`manual`/`scheduled`), безопасный код ошибки. Добавить атомарное получение lease и защиту от публикации устаревшим worker.
- Ограничениями БД обеспечить дедупликацию одинакового задания между процессами. Одной блокировки в памяти недостаточно.
- Хранить серверные настройки: включена ли вечерняя генерация, IANA timezone, локальное время (по умолчанию 21:00), версия настроек и следующий запуск.
- Снимок хранит данные, необходимые для проверки показанных выводов, а не полную копию всех описаний/чек-листов или транскриптов. Удалённый исходник в старом отчёте помечается как недоступный.
- Обеспечить изоляцию owner, каскадное удаление при удалении аккаунта, пагинацию архива, индексы для очереди и выбора периода. Описать обслуживание завершённых заданий; не удалять сохранённые отчёты произвольным TTL.
- Старые localStorage-отчёты автоматически в БД не импортировать. Историю изменения задач, note events и аудит статусов не добавлять.

## Критерии приёмки

- Миграция безопасно применяется к существующим данным; runtime работает без DDL-прав.
- Перезапуск не теряет очередь и последний успешный отчёт.
- Два процесса не создают два отчёта на одно и то же задание; старый lease не позволяет затереть свежий результат.
- Записи отчётов, настроек и очереди одного пользователя недоступны другому.

## Проверки

- Интеграционные тесты миграции, уникальности, конкурентного lease, пагинации, изоляции и перезапуска с настоящей тестовой PostgreSQL.

## Результат реализации

Контракты, код и ограничения описаны в [документации сводок](../docs/SUMMARY-CONTRACTS.md), проверки — в [отчёте приёмки 61–72](ACCEPTANCE-61-72.md). Изменения оставлены без коммита для ревью.
