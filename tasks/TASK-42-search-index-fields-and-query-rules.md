## 1. Цель задачи

Довести локальный полнотекстовый поиск MiniSearch до согласованных правил для командной палитры `⌘K`. Поиск остаётся локальным, использует существующий индекс и возвращает заметки и задачи, не вызывая внешние API или языковые модели.

## 2. Поисковые поля и поведение

- Индексировать заголовок, описание, текст транскрипта, категорию и пользовательские теги (`tags`).
- Искать по заметкам и задачам всех статусов, включая архивные элементы.
- Для запроса из нескольких слов использовать OR-семантику: элемент подходит, если совпало хотя бы одно слово.
- Сохранить префиксный поиск, мягкое исправление опечаток и сортировку MiniSearch по релевантности.
- Возвращать все совпадения без искусственного лимита. Интерфейс может прокручивать длинный список.
- Не менять схему IndexedDB, тип `Item` или механизм синхронизации индекса, если текущих полей достаточно.

## 3. Критерии приёмки

- [x] Поиск находит записи по каждому индексируемому полю, включая пользовательские теги с `#` и без него.
- [x] Результаты включают одновременно заметки и задачи, в том числе архивные.
- [x] При запросе из нескольких слов результат с совпадением только по одному слову остаётся в выдаче.
- [x] Префиксы и небольшие опечатки продолжают находить релевантные записи.
- [x] Совпадения ранжируются по релевантности и не обрезаются по фиксированному числу.
- [x] На локальной базе из 500+ элементов типичный поиск укладывается в целевой бюджет менее 5 мс.

## 4. Проверки

- Добавить unit-тесты для заголовка, описания, транскрипта, категории, пользовательских тегов, архивных элементов, смешанных типов, OR-семантики, префиксов, опечаток и ранжирования.
- Измерять производительность на подготовленном корпусе из 500+ элементов без сетевых запросов.
