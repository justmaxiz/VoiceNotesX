## Выполненные проверки

Использован Node.js 24 из встроенного runtime; системный Node.js 20 не подходит для server package. Эквиваленты команд проекта:

- `npm test`: **43 файла, 263 теста — успешно**.
- `npm run backend:test`: **19 тестов — успешно**.
- `npm run build`: TypeScript + production Vite build — успешно.
- `npm run backend:build`: TypeScript server build — успешно.
- Проверка собранного клиента: имена ключей и адреса Gemini/Yandex не обнаружены в JS/CSS assets. Секреты находятся только на сервере.

Серверные тесты поднимают настоящую отдельную PostgreSQL на свободном IPv4-порту и временное файловое хранилище. Проверены права runtime без DDL, повтор миграции и rollback ошибочной миграции, два владельца, JWT expiry/issuer/audience, CSRF, refresh rotation/reuse, CRUD, реальные WAV/MP3/M4A/WebM/OGG и Opus, размер/длительность (включая ровно 2 часа), приватный Range, истечение ровно 14 дней, удаление короткого аудио, сохранение транскрипта, повтор неудачного удаления, импорт аудио без jobs, перезапуск API/pool и восстановление job, частичное утверждение без дублей. Провайдерные тесты проверяют Gemini, Alice и SpeechKit через подмену HTTP, включая большой файл Gemini Files API с удалением после обработки.

Клиентские проверки покрывают восстановление/смену сессии, один refresh для параллельных 401, серверный store и rollback, гонку обновления списка с редактированием, перенос IndexedDB с подтверждением и сохранением исходника при ошибке, перенос orphan audio session, skeleton/error/retry/raw save, сохранение даты ИИ, восстановление jobs, реальный XHR upload progress и выбор отредактированной части действий.

В тестах остаются предупреждения React `act` в некоторых существующих UI-сценариях; падений и необработанных ошибок нет. Vite предупреждает о размере общего chunk (>500 kB); сборка успешна. Оптимизация загрузки не входила в задачи 45–60.

## Локальная среда

`server/.env` дополнен сгенерированным JWT secret; прежние значения сохранены. Секреты не включены в Git. Для dev базы подготовлен Docker Compose и альтернативная настройка собственной PostgreSQL; инструкция — [server/README.md](../server/README.md).

Docker Desktop/WSL в текущем окружении недоступны. Постоянная dev/staging база и production-инфраструктура не развёрнуты. Для автоматической приёмки использована отдельная нативная PostgreSQL из test dependency, которая остановлена по завершении тестов. Настоящие ИИ API не вызывались.

## Отдельная live/staging приёмка

Эта проверка ожидает внешнюю среду и настоящие ключи; её нельзя считать выполненной по результатам doubles. В TASK-60 это отражено отдельным статусом.

1. В отдельном development окружении задать `AI_PROVIDER=gemini` и серверный `GEMINI_API_KEY`; создать тестовый аккаунт и отправить синтетический текст «Подготовить тестовый отчёт завтра в 15:00». Проверить skeleton → одну сохранённую заметку, расписание, чтение после перезагрузки и на втором клиенте.
2. В российском HTTPS staging окружении задать `NODE_ENV=production`, `AI_PROVIDER=alice`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, разрешённый origin, runtime/migration URLs и приватный persistent audio volume. Выполнить миграции ролью migrator. Проверить health/ready и отсутствие DDL-прав runtime.
3. Отправить синтетический текст и синтетический WAV/MP3 с двумя явно произнесёнными действиями. Проверить SpeechKit → Alice, транскрипт/сводку, выбор одного отредактированного кандидата и отсутствие остальных действий в списке. Не отправлять персональные данные в Gemini.
4. Войти вторым тестовым пользователем; чтение, изменение, удаление чужой заметки/job/аудио должны давать отказ. Проверить refresh после истечения access token, logout, cookie HttpOnly/Secure/SameSite и отклонение чужого Origin.
5. Перезапустить Node во время обработки. Проверить восстановление job после окончания lease и отсутствие дублей; сохранённый транскрипт не должен распознаваться заново при повторе анализа.
6. В отдельной staging БД сократить expiration только у синтетического файла и дождаться cleanup. Проверить 410 для raw audio, доступность заметок/транскрипта и отсутствие файла на диске. Проверить удаление короткой диктовки после обработки.
7. На тестовой браузерной IndexedDB перенести заметки и аудио, прервав соединение посередине. Возобновить перенос, проверить отсутствие дублей/seed и удаление локальной копии только после подтверждения.

Для production отдельно проверить HTTPS proxy/body limits, persistent volume, российское размещение БД/файлов/backups и восстановление из резервной копии. Код не был опубликован и production данные не изменялись.
