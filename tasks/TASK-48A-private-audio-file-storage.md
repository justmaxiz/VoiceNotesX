# TASK-48A: Закрытое файловое хранилище аудио

- **ID:** `TASK-48A`
- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Критический (P0)
- **Зависимости:** `TASK-46`, `TASK-48`

## Цель

Хранить аудиофайлы в закрытой папке backend и выдавать их только владельцу через авторизованный Node API.

## Контекст и связанные части проекта

PostgreSQL хранит аудиометаданные. Бинарные исходники лежат вне web root в папке `AUDIO_STORAGE_PATH`; локально — в игнорируемом каталоге, в production — на диске VPS в РФ. Отдельный объектный сервис для первого этапа не требуется.

## Объём работ

- Создать файловый адаптер записи, чтения и удаления с серверными случайными ключами; пути и владельцы из запроса клиента не используются как доверенные значения.
- Исключить выход за пределы storage root, включая traversal и небезопасные symlink; не публиковать папку как static assets.
- Реализовать авторизованную выдачу файла с проверкой владельца и HTTP Range для воспроизведения; ответы не раскрывают абсолютный путь. Веб-аудиоплеер читает файл по активной серверной сессии из HttpOnly cookie, Expo передаёт bearer token; cookie-проверка для выдачи медиа не предоставляет доступ к изменению заметок.
- Записывать через временный файл и атомарное переименование, согласовать метаданные с успешной записью, убирать незавершённые временные файлы.
- Документировать права папки, постоянный volume при deployment и сохранность данных при перезапуске backend.

## Критерии приёмки

- Файл доступен владельцу через API; без сессии и чужому пользователю выдача отклоняется.
- Подмена ключа/пути не даёт чтения или удаления файла вне storage root.
- Успешная запись переживает перезапуск; ошибка записи не оставляет метаданные успешной загрузки или публичный файл.
- Range-запрос из веб-аудиоплеера с session cookie возвращает корректный участок; отсутствующий/истёкший исходник даёт стабильную ошибку.

## Проверки

- Integration tests записи, чтения, Range, удаления, чужого владельца, traversal и сбоя файловой операции.
- Проверка приватности каталога и сохранности после перезапуска сервера.

## Зависимости

- `TASK-48` — метаданные файла и владелец.
