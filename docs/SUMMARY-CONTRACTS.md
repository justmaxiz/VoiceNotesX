# Сводки v1: контракты и правила

Общий TypeScript/JSON Schema: `server/src/summaryContracts.ts`, схемы всех ответов: `server/src/summarySchemas.ts`. OpenAPI доступен по `GET /api/v1/openapi.json`.

## Период и время

`startDate` включён, `endDateExclusive` исключён. Границы — полночь в IANA `timeZone`, а не UTC/пояс сервера. `asOf` — фактический момент согласованного среза; завершения/создания после него не считаются. Текущие просрочки/ближайшие сроки выделены как факты `timeBasis=current`, результаты периода — `timeBasis=period`. Историческая генерация использует доступное сегодня состояние, не восстанавливает прошлое.

Пресеты: день; текущий день и шесть предыдущих; календарная неделя с понедельника; календарный месяц; произвольный диапазон. Сервер ограничивает диапазон `SUMMARY_MAX_DAYS` (366 по умолчанию). Фильтры категории и тегов независимы. Несколько тегов имеют семантику **любой из тегов**. Категория также входит в поиск по тегу при пустом `tags`; NFKC, удаление `#`, trim, регистронезависимая дедупликация. Общие итоги считают запись один раз; сумма распределения по тегам может превышать число записей.

Сравнение закрытий: предыдущий период той же длины и одинаковое прошедшее число локальных дней/локальное время. Для календарного месяца — предыдущий календарный месяц. Если число прошедших дней не помещается в прошлый месяц либо завершённые месяцы имеют разную длину, сравнение `null`. DST не превращает локальный день в обязательные 24 часа. Для неоднозначного времени берётся первое вхождение; для отсутствующего — первый доступный локальный момент после разрыва. Рост закрытий не называется ростом продуктивности.

## Факты и источники

Вся статистика считается по owner-scoped выборке PostgreSQL без клиентского лимита 200 записей. Выборка заметок, время и формирование фактов не зависят от усечённого LLM-контекста. Чтение facts/последнего отчёта использует `REPEATABLE READ`. `completedAt`, а не `updatedAt`, определяет доступные завершения. Архивные/удалённые/повторно открытые записи не восстанавливают старые завершения. Сохранённые версии остаются снимками.

Нет истории изменения чек-листа/переносов и фактической длительности работы. Плановые минуты суммируют только имеющиеся `estimatedMinutes`, с числом оценок/записей. All-day не означает сутки работы. Пересечения считаются только между явно заданными start/deadline-интервалами, отдельно от просрочек. При импорте происхождение временных меток/автооценок неизвестно.

Модель получает ограниченный набор названий, описаний, чек-листов и разрешённых дат/статусов. Полные транскрипты, файлы, URL аудио, credentials, неподтверждённые кандидаты исключены. Длинное поле пропускается **целиком**, чтобы не убрать условия на середине предложения. Статистика остаётся полной. Снимок сохраняет только метрики, факты и минимальные ID/названия/статусы источников, относящихся к опубликованным блокам. Контекст задания очищается после публикации.

## Проверка LLM

Первая версия использует консервативную extractive-политику: модель выбирает готовые факты и реальные выдержки. Свободные причинные объяснения не публикуются. Highlights требуют завершения именно в выбранном срезе; открытая запись не может стать достижением. Цифры/сроки/просрочки/сравнения берутся из серверных фактов. Неизвестные поля/ID, лишние блоки, несоответствующий статус и неподтверждённые формулировки приводят к явному фактическому fallback. Предложения необязательны и ничего не редактируют.

Минимальный LLM-пример:

```json
{"schemaVersion":1,"overview":{"text":"Завершено записей: 1.","noteIds":[],"factIds":["fact:completed"]},"highlights":[],"observations":[],"themes":[],"suggestions":[]}
```

Полный API-пример сохранён в [summary-api-example.json](summary-api-example.json). LLM не возвращает `metrics`: они добавляются сервером. `generationMode=ai|facts|empty`; свежесть `current|stale|historical_snapshot` независима от задания `queued|running|completed|error`.

## API

Все маршруты требуют сессии. Owner/готовые метрики в запросе не принимаются.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/summaries/facts?period=<JSON>` | Факты и последняя опубликованная версия; не вызывает модель |
| `POST /api/v1/summaries/generate` | Тело SummaryPeriod; 202 с job либо 200 с кешем/fallback |
| `GET /api/v1/summaries/jobs/:id` | Stage, attempts, безопасная ошибка и reportId |
| `GET /api/v1/summaries/reports/:id` | Снимок, текущая свежесть и доступность источников |
| `GET /api/v1/summaries/archive?offset=0&limit=20` | Последняя опубликованная версия каждого слота; nextOffset, предел 50 |
| `GET/PATCH /api/v1/summaries/settings` | enabled, timeZone, localTime, version, nextRun |

PATCH `initialize=true` задаёт определённый браузером пояс только при отсутствии настроек; явно выбранный пояс другого устройства не перезаписывается. Без timezone расписание не запускается. Поля owner/version/nextRun клиент не изменяет. Default time — 21:00.

## Кеш, очередь и восстановление

Fingerprint покрывает полный релевантный набор, сравнение и дискретные временные факты, версию генератора/провайдера/модели/лимитов. Не содержит каждую секунду now. GET и редактирование записей не запускают модель. UNIQUE `(owner,slot,fingerprint)` и owner advisory lock объединяют manual/scheduled даже между процессами. Успешные сохранённые fingerprints переиспользуются после очистки jobs.

Очередь получает атомарный lease 120 секунд с новым UUID. Публикация проверяет lease/token и блокирует слот; старый worker не перезаписывает восстановленный результат. После сбоя процесса возможна одна повторная попытка (всего 2 claim); при отказе модели сразу публикуется fallback. Пользователь может явно повторить ошибочное задание с тем же входом, пока не исчерпаны две попытки; повтор учитывается в часовом бюджете. Конкурентные повторы объединяются. Успешная предыдущая версия остаётся в слоте, новый fallback доступен через job.reportId. Timeout провайдера 30 секунд, внешний предел worker 35 секунд. Просроченные lease после второго claim завершаются безопасной ошибкой.

Следующий scheduled запуск хранится в БД; due-строки блокируются `FOR UPDATE SKIP LOCKED`. Catch-up берёт только последнюю пропущенную локальную дату, с фактическим текущим `asOf`. Ошибка аккаунта переносит его следующий запуск и не останавливает остальные. Смена конфигурации пересчитывает nextRun атомарно. Неизменный ручной отчёт вечером использует кеш. Push/email не предусмотрены.

`buildApp` запускает scheduler/worker вместе с Node API; API должен работать непрерывно. Интервал обслуживания 15 секунд, до 10 jobs за проход. Глобальная параллельность и один running lease на owner проверяются в БД. Завершённые/ошибочные jobs старше 30 дней удаляются; отчёты не имеют TTL. Runtime использует SELECT/INSERT/UPDATE/DELETE без DDL, права наследуются через уже настроенные default privileges migrator.

## Клиент

Typed repository и Zustand state общие для карточки и страницы. Ключ owner/нормализованный период; чтение/генерация дедуплицируются. Polling ограничен 30 попытками с ростом 1–10 секунд; уход последнего consumer, logout и 401/403 останавливают его. Поздние ответы другого владельца игнорируются. Повторное открытие, focus/online/visibility выполняют чтение. Смена данных помечает кеш stale и читает факты без LLM.

Offline JSON имеет owner/schemaVersion/savedAt и проверяется перед отображением. Ошибка БД не становится пустой статистикой. Копирование/Markdown используют один formatter сохранённого снимка, включая внимание и ограничения; отказ clipboard не показывает успех. Legacy adapter read-only читает только owner-scoped прежний ключ. Anonymous/unscoped архивы не усваиваются текущим аккаунтом и не импортируются на сервер.
