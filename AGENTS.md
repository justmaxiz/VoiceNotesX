# Правила разработки и тестирования проекта VoiceNotes AI

## Стратегия тестирования и экономия ресурсов
1. **Полное тестирование (`npm test` / полный запуск Vitest):**
   - Запускать **исключительно** при затрагивании фундаментальных компонентов архитектуры приложения:
     - Изменение ключевых типов и контрактов данных (`src/types/`).
     - Архитектура хранилища и стейт-менеджмент (`Dexie.js`, `IndexedDB`, `Zustand store`).
     - Глобальный роутинг и критическая логика каркаса (`AppLayout`, `navigationStore`).
     - Аудио-движок и интеграция с внешними API (MediaRecorder, Gemini API).
2. **Локальные и косметические изменения:**
   - Для правок верстки, компонентов, Tailwind-классов, текстов, иконок и локальных правок UI **НЕ запускать** полный тестовый сьют.
   - Ограничиваться быстрой проверкой синтаксиса и типов: `npm run build` или `npx tsc --noEmit`.
   - При необходимости проверки конкретного измененного компонента запускать только его изолированный файл: `npx vitest run <path-to-test>.test.tsx`.
