# TASK-45A: Подключение PostgreSQL и миграции

- **ID:** `TASK-45A`
- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Критический (P0)
- **Зависимости:** `TASK-45`

## Цель

Подключить Node API к PostgreSQL и подготовить воспроизводимый механизм изменения схемы перед реализацией авторизации и заметок.

## Контекст и связанные части проекта

В `server/` есть Fastify-каркас с health endpoint. PostgreSQL работает отдельно; доступна только backend-серверу. Production-база, аудиофайлы и резервные копии размещаются в РФ.

## Объём работ

- Добавить драйвер `pg`, ограниченный connection pool, тайм-ауты подключения/запроса и закрытие pool при остановке сервера.
- Читать `DATABASE_URL` для runtime и `MIGRATION_DATABASE_URL` для миграций только из server env. Отсутствующая/неверная конфигурация должна давать понятную ошибку без вывода credentials.
- Добавить отдельные команды применения версионированных SQL-миграций; хранить историю применённых версий и исключить одновременное выполнение миграций.
- Добавить readiness endpoint с проверкой БД и ответом `503` при недоступной базе; существующий health endpoint остаётся независимым от БД.
- Документировать создание отдельной тестовой базы и запрет выполнения проверок/миграций тестов на production-базе.

## Критерии приёмки

- Сервер соединяется с локальной PostgreSQL через runtime role; credentials не попадают в клиент или лог.
- Недоступная БД приводит к `503` readiness, health endpoint продолжает работать.
- Повторное применение миграций не выполняет применённые версии заново; ошибка не оставляет частично применённую транзакционную миграцию.
- Runtime role не может изменять схему; миграции выполняются отдельно от API-запросов.

## Проверки

- Серверная сборка; smoke проверки подключения, закрытия pool и отказа readiness.
- Применение миграций дважды на пустой тестовой базе; проверка отката неуспешной миграции и прав ролей.
