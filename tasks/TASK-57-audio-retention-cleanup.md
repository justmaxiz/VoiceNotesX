# TASK-57: Удаление аудио по сроку хранения

- **ID:** `TASK-57`
- **Блок:** 9. Облачный backend и ИИ-обработка ввода
- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-48`, `TASK-48A`, `TASK-56`

## Цель

Соблюдать срок хранения исходного аудио: короткие запросы удалять после обработки, загруженные большие файлы — через 14 дней.

## Контекст и связанные части проекта

Транскрипты, сводки и утверждённые заметки остаются в PostgreSQL. Большие импортированные файлы хранятся ограниченный срок в закрытой папке backend.

## Объём работ

- После завершения или окончательной ошибки короткого аудиозапроса удалить временный raw audio.
- Добавить серверную scheduled cleanup job для файлов с `expiresAt <= now`, установленным ровно через 14 дней после загрузки.
- После удаления файла пометить аудиоисточник как expired; оставить доступными текст транскрипта, сводку, заметки и утверждённые задачи.
- Сделать очистку идемпотентной, журналировать ошибки без содержимого аудио и повторять временно неуспешные удаления.
- Не удалять файл по переданному клиентом владельцу/пути; cleanup использует доверенные PostgreSQL-метаданные и файловый адаптер, ограниченный storage root.

## Критерии приёмки

- Короткий исходник удаляется после процесса и недоступен через API выдачи файлов.
- Большой исходник доступен до истечения 14 дней и удалён после срока; при удалении текстовый результат остаётся доступен.
- Повторный запуск cleanup безопасен и не удаляет аудио, срок которого ещё не истёк.
- Статус истёкшего аудио отражается в API так, чтобы клиент не показывал неработающий плеер.

## Проверки

- Unit-тесты с управляемыми часами для точной границы 14 дней.
- Тест идемпотентности, частичной ошибки файлового удаления и сохранения текстовых данных.

- `TASK-56` — загрузка и audio jobs.
