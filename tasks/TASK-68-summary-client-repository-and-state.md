# TASK-68: Клиентский репозиторий сводок и общее состояние

- **ID:** `TASK-68`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-61`, `TASK-66`, `TASK-51`

## Цель

Перевести клиент на серверные отчёты и дать странице сводок/дашборду единый источник данных, не запуская генерацию при каждом render.

## Объём работ

- Создать typed repository для статистики, отчётов, архива, генерации и статуса jobs через существующий `api.ts`. Параметры периода и фильтры нормализуются по общему контракту.
- Выделить состояние запросов по owner + period + filters; хранить отдельно последнюю успешную версию, загрузку фактов, обновление ИИ, ошибку и актуальность.
- Дедуплицировать чтение и запросы генерации между компонентами. Открытие страницы/дашборда выполняет чтение; генерация только по кнопке либо серверному расписанию.
- Наблюдать queued/running jobs ограниченным polling с backoff, останавливать его после завершения/ошибки, ухода из аккаунта или отсутствия заинтересованных компонентов. Не продолжать бесконечный polling после 401/403.
- При смене периода не смешивать результаты; при смене аккаунта очищать state и отменять/игнорировать поздние ответы. Пользователь B не должен видеть кеш A.
- После успешных изменений записей помечать затронутый отчёт потенциально stale и обновлять серверные факты без вызова LLM; сервер остаётся источником истины. Изменения на другом устройстве обнаруживать при повторном чтении/возврате вкладки.
- Локальный кеш последнего отчёта допустим только с owner scope, версией схемы и временем. При offline показывать сохранённый снимок с меткой; отсутствие кеша не подменять пустой статистикой.
- Не читать localStorage-архив как серверный результат. Удаление локального digest scheduler согласовать с TASK-67; доступ к legacy данным оставить для TASK-71.

## Критерии приёмки

- Дашборд и страница используют одну версию отчёта и не создают второй LLM-запрос.
- Failed refresh сохраняет последнюю успешную версию, загрузка фактов отличается от загрузки ИИ.
- Logout/account switch, отменённый запрос и поздний ответ не приводят к утечке кеша или неверному периоду.
- Offline/DB failure не показываются как «задач нет».

## Проверки

- Изолированные repository/store/hook-тесты с API doubles: dedup, polling, account switch, stale и offline.
- Сборка; полный Vitest при изменении архитектуры состояния согласно `AGENTS.md`.

## Результат реализации

Контракты, код и ограничения описаны в [документации сводок](../docs/SUMMARY-CONTRACTS.md), проверки — в [отчёте приёмки 61–72](ACCEPTANCE-61-72.md). Изменения оставлены без коммита для ревью.
