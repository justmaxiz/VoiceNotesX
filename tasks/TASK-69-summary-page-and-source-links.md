# TASK-69: Компактный интерфейс сводок и переходы к источникам

- **ID:** `TASK-69`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-68`

## Цель

Переработать `AiSummariesPage` в быстро считываемую сводку: реальные показатели, короткий итог, результаты, внимание и возможные следующие шаги с источниками.

## Объём работ

- Сохранить существующую дизайн-систему; заменить локальный `handleGenerate` серверным запросом. Удалить фиктивный глобальный 30-секундный cooldown; показывать pending и реальные server limits/retry-after.
- Добавить выбор периода: день, последние семь дней/календарная неделя, месяц и диапазон; тег — независимый фильтр из пользовательских данных, не три фиксированные кнопки.
- Показать период, timezone, время среза/генерации и актуальность. Текущий период допускает обновление; пересчёт исторического снимка явно обозначается как новая версия по текущим данным.
- Порядок блоков: строка фактических показателей, краткий итог, до трёх результатов, до двух наблюдений внимания, направления/сопоставимое сравнение, до двух предложений.
- Пустые содержательные блоки скрывать. Для одного результата не создавать большой пустой отчёт. Не дублировать счётчики в каждом текстовом блоке.
- Заменить «Блокеры» на «Требует внимания»; не называть рост закрытий доказанной продуктивностью. При ограниченном контексте дать короткое пояснение покрытия.
- Источники открывают существующую панель записи по ID; если запись удалена/недоступна, показать это состояние и сведения снимка вместо сломанного перехода.
- Отобразить факты сразу после загрузки, старую сводку оставить при обновлении. Без старой версии skeleton только в блоках ИИ. При ошибке — понятная причина/повтор и фактический fallback с честной меткой режима.
- Различать пустой период, ошибку БД, unavailable LLM и offline-снимок. Рекомендации не создают задачи и не меняют даты автоматически.
- Архив получает серверную пагинацию; отображать последнюю версию слота без повторных карточек одного отчёта. Формат должен оставаться компактным на мобильном экране.

## Критерии приёмки

- Сводку можно прочитать без раскрытия длинного текста; показаны источники и ограничения данных.
- Loading/error/stale/fallback/empty состояния работают независимо от наличия прошлой успешной версии.
- Фильтры соответствуют данным пользователя и периоду; показатели «к анализу» не считают все записи аккаунта без фильтра.
- Управление доступно с клавиатуры, pending/ошибки корректно объявляются assistive technologies.

## Проверки

- Изолированный `AiSummariesPage` тест: все состояния, источники, фильтры, пагинация и защита от повторного клика.
- Визуальная проверка desktop/mobile и клиентская сборка. Для локальной верстки полный Vitest не запускать.
