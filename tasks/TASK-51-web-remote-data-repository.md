# TASK-51: Перевод веб-клиента на backend-репозитории

- **ID:** `TASK-51`
- **Блок:** 9. Облачный backend и ИИ-обработка ввода
- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Критический (P0)
- **Зависимости:** `TASK-49`, `TASK-50`, `TASK-48A`

## Цель

Сделать backend источником заметок и аудиоданных в веб-клиенте и убрать прямые обращения пользовательских потоков к Dexie.

## Контекст и связанные части проекта

Основной store находится в `src/store/useAppStore.ts`; `src/lib/db.ts` обслуживает Dexie, а аудио, экспорт, seed data и отдельные сервисы вызывают базу напрямую. Будущие мобильные клиенты будут обращаться к тем же API, а не к локальной схеме браузера.

## Объём работ

- Добавить типизированные API repositories для заметок и аудиометаданных и подключить их к `useAppStore`.
- Заменить прямой доступ к пользовательским `items`/`audioSessions` в Quick Capture, drawer, аудиоплеере, экспорте и загрузке приложения на API-контракт.
- Оставить локальный поиск и UI-настройки клиентскими, если для них не требуется хранить пользовательское содержимое.
- Убрать production seed-операции, которые записывают примерные заметки в пользовательский аккаунт.
- Сохранять server error/optimistic rollback в store и явно показывать состояние сети; локальная база не становится запасным источником истины.

## Критерии приёмки

- Все новые и изменённые заметки читаются и сохраняются через Node API; ни один основной поток не записывает их в IndexedDB.
- Аудиофайлы не сохраняются браузером как долговременный источник; веб-аудиоплеер использует защищённую выдачу Node API с session cookie и HTTP Range. Настроить cookie credentials/CORS и не помещать access token в URL.
- Поиск, drawer, календарь, экспорт и списки продолжают использовать единый remote-backed store.
- При сетевой ошибке данные пользователя не помечаются сохранёнными, а UI сохраняет ввод для повтора.

## Проверки

- Тесты store с подменным API для CRUD, загрузки, отката ошибки и смены пользователя.
- Поиск прямых production вызовов Dexie для пользовательских записей и ручная проверка основных страниц.
- Из-за изменений store/контракта выполнить предусмотренный `AGENTS.md` полный прогон Vitest и сборку.
