# TASK-63: Отбор контекста и источников для ИИ-сводки

- **ID:** `TASK-63`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-61`, `TASK-62`

## Цель

Подготовить компактный, воспроизводимый запрос модели с реальными пользовательскими данными и явными ограничениями покрытия.

## Объём работ

- Создать серверный builder контекста: период, `asOf`, агрегаты, факты, выбранные исходные записи, сравнение и ограничения качества данных.
- Разрешённые текстовые поля: названия, описания, релевантные пункты чек-листов задач и заметок. Добавлять необходимые статусы, приоритеты, категории, теги и даты.
- Полностью исключить `transcriptText`, полные транскрипты `audio_jobs`, аудио, URL файлов, credentials и неподтверждённые аудиокандидаты. Не подменять отсутствующее описание транскриптом.
- Детерминированно отбирать результаты, важные открытые дела, просрочки, ближайшие сроки и заметки периода. Ранжирование использует приоритет, фокус, сроки и релевантность; порядок получения API не является важностью.
- При большом объёме ограничивать число записей, длину каждого поля и общий входной бюджет. Лимиты настраиваются сервером; сохранять необходимые условия текста и отмечать сокращение. Не обещать анализ всего текста после усечения.
- Передавать статистику полного набора и `coverage`: число учтённых/отобранных записей, сокращённых текстов, отсутствие истории/фактической длительности. Дедуплицировать исходники.
- Формировать стабильные ссылки на разрешённые `noteIds` и `factIds`; хранить минимальные подтверждающие данные для результата. Составить правила, какие типы выводов допустимы при каждом покрытии.
- Числа, даты и признаки просрочки передавать готовыми фактами; не поручать модели арифметику. Не использовать старые ИИ-сводки как единственный источник недельного/месячного анализа.
- Пользовательские описания и чек-листы передавать как данные, отделённые от системных инструкций. Сводка не получает инструменты изменения задач.
- Подготовить синтетические эталонные наборы: небольшой день, смешанная неделя, заметка с обязательством без даты, большой период, противоречивый текст, prompt injection.

## Критерии приёмки

- Payload воспроизводим, ограничен по объёму и содержит только разрешённые поля владельца.
- Ни транскрипты, ни чужие записи не попадают в запрос независимо от наличия их в БД.
- Отбор не меняет статистику полного периода, а ограничения видимы в `coverage`.
- Запись без расписания не объявляется выполненной задачей только по содержанию описания.

## Проверки

- Изолированные проверки whitelist полей, сортировки, бюджета и усечения условий.
- Проверки полного исключения транскриптов и adversarial-текстов без настоящего AI API.
