# TASK-65: Генерация ИИ-наблюдений и проверка достоверности

- **ID:** `TASK-65`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-61`, `TASK-63`, `TASK-54`

## Цель

Расширить серверный AIProvider отдельной операцией сводки и возвращать короткий проверенный JSON, основанный на подготовленных источниках.

## Объём работ

- Добавить отдельный метод для периодических сводок. Не использовать существующий `analyze` с контрактом аудиокандидатов и не менять его поведение.
- Сохранить разделение провайдеров: production → Alice; Gemini только для development на синтетических данных. Ключи остаются на сервере.
- Системный prompt определяет роль редактора: выбирать существенные результаты, объединять темы, объяснять внимание и давать максимум два необязательных предложения. Не пересказывать весь список.
- Запретить арифметику, выдуманные сроки/зависимости/результаты, причины задержек, повторные переносы, фактические часы работы и оценки личности/продуктивности. Намерение из заметки не выдавать за выполненное действие.
- Проверять JSON Schema, лимиты текста и блоков, обязательные источники, allowlist ID, принадлежность владельцу и соответствие типу вывода. Открытая запись не может быть единственным основанием достижения.
- Критичные утверждения о количестве, сроках, просрочках и сравнении формировать из типизированных фактов проверенным кодом/шаблонами. Модель может выбирать эти факты и объяснять их; произвольная текстовая цифра не заменяет факт.
- Ссылки на источник не считать автоматическим доказательством свободной формулировки. Семантические выводы ограничивать данными источников; недопустимый ответ не публиковать. Определить политику: один ограниченный повтор в общем бюджете либо фактический fallback.
- Разрешить пустые наблюдения/рекомендации; при отсутствии значимых данных не генерировать общие советы ради заполнения секций.
- Настроить отдельный лимит выходных токенов и timeout, нормализованные ошибки. Считать доступные usage-метрики без журналирования пользовательского payload и полного ответа.

## Критерии приёмки

- Корректный результат проходит проверку и содержит только подтверждённые источники.
- Чужие/несуществующие ID, выдуманные даты, перевыполненные лимиты и неверный статус не публикуются.
- Отказ модели не затирает предыдущий отчёт и не маскируется под успешную ИИ-генерацию.
- Работа новой операции не нарушает структурирование, аудиоанализ и матрицу провайдеров.

## Проверки

- Provider doubles: корректный ответ, malformed/empty JSON, неизвестные источники, неподтверждённые цифры, injection, timeout и unavailable.
- Изолированные backend-тесты и сборки; полный Vitest при изменении интеграции внешнего API согласно `AGENTS.md`. Live smoke — отдельно на синтетических данных.
