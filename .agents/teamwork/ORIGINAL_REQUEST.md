## Requirements

### R1. Структура данных и хранилище
Добавить поддержку времени начала (`startDate`) для задач. Существующее поле `deadline` должно использоваться как время окончания задачи.

### R2. Логика автоматического и ручного фокуса
Реализовать систему выбора текущей задачи. Приоритеты фокуса (от высшего к низшему):
1. **Срочная задача (ручной фокус):** Пользователь вручную выделил задачу, время которой еще не наступило. Она удерживает фокус до завершения или ручного снятия.
2. **Просроченные задачи:** Время `deadline` прошло, а задача не завершена. При наличии нескольких просроченных, в фокус берется самая старая из них (по `deadline`).
3. **Текущая задача:** Текущее системное время попадает в интервал между `startDate` и `deadline`.

### R3. UI Календаря
В компоненте календаря задачи должны визуально растягиваться на весь свой временной интервал (от `startDate` до `deadline`), занимая соответствующее визуальное пространство на сетке расписания, а не отображаться как точечные события.

## Acceptance Criteria

- [ ] Агент-судья подтверждает: ручной фокус на будущую задачу не сбрасывается при наступлении времени другой задачи.
- [ ] Агент-судья подтверждает: если есть задача с `deadline` вчера и задача с `deadline` сегодня, фокус автоматически устанавливается на вчерашнюю.
- [ ] Агент-судья подтверждает: если текущее время находится внутри интервала некой задачи, и нет просроченных или вручную сфокусированных задач, эта задача получает фокус.
