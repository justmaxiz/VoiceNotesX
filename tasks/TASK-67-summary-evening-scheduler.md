# TASK-67: Вечерняя генерация на сервере и настройки расписания

- **ID:** `TASK-67`
- **Блок:** 10. ИИ-сводки с проверяемыми наблюдениями
- **Статус:** Реализовано; автоматические проверки выполнены
- **Приоритет:** Высокий (P1)
- **Зависимости:** `TASK-64`, `TASK-66`

## Цель

Автоматически формировать дневную сводку вечером, даже когда приложение закрыто, с учётом часового пояса пользователя и без дублирования ручной генерации.

## Объём работ

- Добавить авторизованные GET/PATCH API настроек: включение вечернего отчёта, IANA timezone, локальное время; по умолчанию 21:00. Включение/отключение относится к генерации, а не разрешению browser notifications.
- В клиентских настройках показать эти параметры. При первом входе/обновлении версии отправить определённый браузером timezone один раз, если серверная настройка ещё отсутствует; не перезаписывать явно выбранный пояс при смене устройства.
- Для аккаунта без достоверного timezone не угадывать серверный пояс: показать необходимость настройки, до её появления автоматический запуск не выполнять. Ручной период может передавать валидный явный timezone.
- Планировщик выбирает due-настройки из PostgreSQL и создаёт задания через общий сервис TASK-66. Публикация использует worker/lease TASK-64; несколько процессов не дублируют запуск.
- Обеспечить восстановление после перезапуска. Catch-up ограничить последним пропущенным дневным запуском, без массовой генерации за весь простой; сохранять время фактического среза, не выдавать текущие данные за состояние вчера в 21:00.
- Смена timezone/времени атомарно пересчитывает следующий запуск; определить поведение повторяющегося/отсутствующего локального времени при DST и гарантировать не более одного scheduled-запуска на локальную дату/конфигурацию.
- При наличии ручного отчёта обновлять его вечером только при изменившемся релевантном входе. При неизменных данных использовать кеш. Изменения после вечернего среза помечают отчёт устаревшим без немедленного LLM-запроса.
- Пропускать пустые периоды без вызова модели; ограничивать retry/backoff, respecting owner/system limits. Ошибка одного аккаунта не останавливает планировщик.
- Удалить старый браузерный `startDailyDigestScheduler` и подключение в `AppLayout` после готовности клиентского перехода TASK-68. Не отключать планировщик напоминаний.
- Не добавлять push/email-доставку при закрытом приложении в эту задачу; отчёт появляется в аккаунте при следующем открытии. Не обещать уведомление там, где нет механизма доставки.

## Критерии приёмки

- Два пользователя с разными поясами получают отчёты в свои локальные вечерние часы при закрытых клиентах.
- Перезапуск, два worker и ручной запрос рядом со scheduled не приводят к лишним LLM-вызовам.
- Отчёт обозначает «на 21:00» или фактическое время среза, а не полный завершённый день.
- Настройки сохраняются между устройствами; browser timer больше не создаёт локальные отчёты.

## Проверки

- Fake clock + тестовая PostgreSQL: timezone, DST, смена настроек, catch-up, отключение, кеш, retry и несколько процессов.
- Изолированный тест SettingsPage; полный Vitest при изменении критического `AppLayout` согласно `AGENTS.md`.
