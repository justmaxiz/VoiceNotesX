# TASK-48: Схема PostgreSQL и изоляция данных

- **ID:** `TASK-48`
- **Блок:** 9. Облачный backend и ИИ-обработка ввода
- **Статус:** Реализовано; автоматические проверки пройдены
- **Приоритет:** Критический (P0)
- **Зависимости:** `TASK-46`, `TASK-47`

## Цель

Создать PostgreSQL-миграции для заметок и аудиообработки, обеспечить принадлежность данных пользователю и изоляцию операций через Node API.

## Контекст и связанные части проекта

`src/lib/db.ts` сейчас создаёт локальные таблицы `items`, `audioSessions` и `settings`. В новом устройстве пользовательские заметки и аудио принадлежат аккаунту и доступны через Node API; большие загруженные файлы должны храниться временно.

## Объём работ

- Добавить SQL-миграции для единой таблицы заметок и метаданных аудио/обработки; таблицы пользователей и сессий созданы в `TASK-46`.
- Добавить внешние ключи владельца, индексы для списков/расписания и ограничения полей по контракту `TASK-47`; связь заметки с аудио должна исключать привязку к чужому владельцу.
- Хранить временное состояние audio job отдельно от постоянного результата: транскрипт и заметки остаются после истечения срока исходного файла.
- Хранить в PostgreSQL ключ файла, размер, MIME-тип, владельца и `expiresAt`, а исходные аудиобайлы хранить отдельно в `TASK-48A`.
- Ограничить все операции репозитория по `owner_id` из проверенной сессии; использовать параметризованные SQL-запросы. Клиенты не имеют подключения к PostgreSQL.
- Использовать отдельные роли для миграций и работы API: runtime role не является superuser и не имеет прав изменения схемы.

## Критерии приёмки

- Чистая PostgreSQL-база создаётся миграциями и содержит необходимые таблицы, индексы и ограничения.
- Пользователь A не читает, не изменяет и не удаляет записи или файлы пользователя B.
- Удаление аудиофайла не удаляет транскрипт, утверждённые заметки или результаты обработки.

## Проверки

- Проверка миграций на пустой базе.
- Интеграционные тесты репозитория для двух пользователей, подмены владельца и привязки чужого аудио.
- Проверка типов и обязательных полей audio job/expiration metadata.

## Зависимости

- `TASK-46` — идентификатор и правила владельца.
- `TASK-47` — единый контракт заметки.
