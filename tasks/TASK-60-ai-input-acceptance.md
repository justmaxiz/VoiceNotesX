# TASK-60: Сквозная приёмка ИИ-ввода и облачной синхронизации

- **ID:** `TASK-60`
- **Блок:** 9. Облачный backend и ИИ-обработка ввода
- **Статус:** Автоматическая приёмка выполнена; live/staging smoke ожидает внешнюю среду
- **Приоритет:** Критический (P0)
- **Зависимости:** `TASK-45`–`TASK-59`, включая `TASK-45A` и `TASK-48A`

## Цель

Проверить сквозные сценарии текста, диктовки и файла на серверной архитектуре до передачи задачи в приёмку.

## Контекст и связанные части проекта

Новые потоки пересекают Node auth/REST API, PostgreSQL, закрытое файловое хранилище, client store, AI provider и аудио UI. Успешный `vite build` не подтверждает изоляцию пользователей, жизненный цикл файлов или восстановление jobs.

## Объём работ

- Добавить интеграционный набор с подменными Gemini, Alice и SpeechKit adapters, отдельной PostgreSQL тестовой базой и временной закрытой папкой аудио. Для проверки владения/миграций использовать настоящую тестовую PostgreSQL, API doubles допустимы для клиентских тестов.
- Покрыть создание текста, живую диктовку, skeleton, валидный ответ, ошибку/пустой/некорректный ответ, retry и сохранение исходного текста.
- Покрыть импорт аудио, лимиты, стадии job, транскрипт, утверждение части кандидатов и изоляцию другого пользователя.
- Проверить короткое аудио после удаления и файл после истечения 14 дней; подтвердить, что транскрипты и заметки остаются.
- Выполнить миграцию старых локальных данных на тестовом наборе и проверить повторный запуск без дублей.
- Не требовать доступа к живым AI API для обычного CI; тестировать конфигурационную матрицу Gemini в development и Alice + SpeechKit в production, включая отказ production при выборе Gemini.
- Отдельный live smoke test выполнять только на синтетических данных; не направлять персональные данные в Gemini.

## Критерии приёмки

- Текстовый и голосовой ввод создаёт одну серверную заметку; наличие расписания управляет отображением в заметках/задачах.
- Ошибка модели сохраняет текст и позволяет повторить попытку.
- Аудиокандидаты не сохраняются до утверждения; после подтверждения создаются только выбранные записи.
- Удаление исходного аудио соблюдает сроки, а серверная изоляция не допускает чтения чужих данных.
- `npm run build`, серверная сборка и полный `npm test` проходят; staging smoke test описан отдельно и не подменяется mock-тестами.

## Проверки

- Запустить полный Vitest и клиентскую/серверную сборки после интеграции, поскольку меняются типы, store, API и аудиообработка.
- Выполнить полный сценарий на двух тестовых пользователях с подменным provider.
- Проверить отдельный live smoke test обеих сред на синтетическом запросе: development → Gemini; production → Alice и SpeechKit. В CI использовать только doubles.
- При доступной staging среде сделать отдельный smoke test auth → AI → PostgreSQL save → private audio → cleanup; проверить перезапуск Node API и восстановление jobs из базы.
